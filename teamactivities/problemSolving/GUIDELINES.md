# Team Problem Solving Guidelines

## Purpose
This document outlines how to effectively use problem statements to develop team problem-solving skills.

## Weekly Structure

### Day 1-2: Problem Release
- Announce new problem
- Provide problem statement and examples
- Team members work independently
- Document approach and solutions

### Day 3-4: Solution Presentation
- Team members present their solutions
- Discuss different approaches
- Identify pros and cons of each solution
- Share learnings

### Day 5: Deep Dive
- Review optimal solution
- Discuss optimization techniques
- Identify real-world applications
- Plan for next problem

## Expectations for Participants

### Before Problem Discussion
- ✅ Attempt the problem independently
- ✅ Document your approach
- ✅ Test your solution with examples
- ✅ Note challenges encountered

### During Discussion
- ✅ Be respectful of different approaches
- ✅ Ask clarifying questions
- ✅ Share insights freely
- ✅ Help team members understand
- ✅ Challenge assumptions constructively

### After Discussion
- ✅ Implement feedback
- ✅ Understand alternative approaches
- ✅ Document learnings
- ✅ Mentor others

## Evaluation Criteria

| Aspect | Description |
|--------|-------------|
| **Correctness** | Solution handles all test cases |
| **Efficiency** | Optimal time and space complexity |
| **Code Quality** | Readable, well-documented code |
| **Problem Solving** | Clear approach and methodology |
| **Communication** | Ability to explain solution |
| **Collaboration** | Helping teammates, open to feedback |

## Resources by Problem Type

### Beginner Problems
- Focus: Basic syntax, logic, fundamentals
- Concepts: Loops, conditionals, data structures
- Tools: IDE, online judges (LeetCode, HackerRank)
- Time: 5-15 minutes per problem

### Intermediate Problems
- Focus: Algorithms, optimization, design patterns
- Concepts: Sorting, searching, trees, graphs
- Tools: Debuggers, profilers, complexity analyzers
- Time: 20-45 minutes per problem

### Advanced Problems
- Focus: System design, architecture, scalability
- Concepts: Distributed systems, databases, caching
- Tools: Design tools, documentation
- Time: 60+ minutes per problem

### Case Studies
- Focus: Real-world scenarios, business logic
- Concepts: Complete systems, trade-offs, requirements
- Tools: Whiteboarding, documentation
- Time: 90+ minutes per problem

## Problem Progression

```
Week 1-2:   2 Beginner problems
Week 3-4:   1 Beginner + 1 Intermediate
Week 5-6:   1 Intermediate + 1 Advanced
Week 7-8:   1 Advanced + 1 Case Study
Week 9-12:  Mixed problems + team challenges
```

## Tips for Success

### For Individuals
1. **Read carefully**: Understand constraints and requirements
2. **Think first**: Plan before coding
3. **Start simple**: Get basic solution working
4. **Optimize**: Improve efficiency after correctness
5. **Test thoroughly**: Check edge cases
6. **Ask questions**: Clarify before assuming

### For the Team
1. **Share learnings**: Post solutions in shared folder
2. **Code reviews**: Review peer solutions
3. **Discuss approaches**: Why did you choose that method?
4. **Learn together**: Celebrate diverse solutions
5. **Iterate**: Improve based on feedback

## Assessment

### Self-Assessment Checklist
- [ ] I understood the problem completely
- [ ] My solution is correct for all examples
- [ ] I considered edge cases
- [ ] My code is clean and well-commented
- [ ] I can explain my approach to others
- [ ] I learned something new

### Leader Assessment
- Problem selection appropriateness
- Team participation rate
- Solution quality improvements
- Knowledge transfer effectiveness
- Team confidence growth
